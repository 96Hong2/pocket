# 0016. 사진·줄글 인식은 Gemini 2.5 Flash 를 기본으로, OpenAI 를 예비로 두고 SDK 없이 부른다

상태: 확정 · **PRD 가 정하지 않아 우리가 정했다** · 2026-09-08

## 배경

캡처·영수증·줄글 세 입구가 같은 포트(`LlmStructuredClient.extract`)를 지나고, 그 뒤에 붙은 것은
규칙 기반 스텁뿐이었다. 스텁은 사진을 한 바이트도 읽지 않고 정해 둔 예시를 낸다. 출시 가이드가
「키만 넣으면 된다」고 적어 뒀는데, 열어 보니 키 자리도 어댑터도 없었다.

사용자가 후보 셋(Gemini 2.5 Flash · GPT-5 mini · Claude Haiku 4.5)을 보고 "Gemini 랑 GPT 둘 다
쓸 수 있게 하고, 일단 Gemini 로" 라고 정했다.

## 결정

1. **provider 는 설정 하나로 갈린다.** `LLM_PROVIDER=stub|gemini|openai`. 기본은 `stub` 이라
   키 없이 개발·검증이 돌고, 운영은 `gemini` 로 띄운다. 키가 없는 provider 를 고르면 기동에 실패한다.
2. **Gemini 2.5 Flash 가 기본, gpt-5-mini 가 예비.** 모델 이름은 `LLM_MODEL` 로 바꿀 수 있다.
3. **SDK 를 넣지 않는다.** 두 provider 모두 요청 하나·응답 하나라 이미 있는 httpx 로 부른다.
4. **키는 유료 등급 프로젝트의 것만 쓴다.** Gemini 무료 등급은 보낸 입력을 제품 개선에 쓰고 사람이
   읽을 수 있다. OpenAI 는 `store: false` 로 보내 응답 저장을 끈다.
5. **원문은 어디에도 남기지 않는다.** 어댑터가 로그에 남기는 것은 상태코드·토큰 수·걸린 시간뿐이고,
   응답 검증 실패도 어느 필드가 틀렸는지만 남긴다.
6. **검증은 provider 와 무관하게 스텁이다.** `tests/conftest.py` 와 `e2e/support/servers.ts` 가
   `.env` 보다 센 환경변수로 스텁을 못 박는다.

## 근거

- **값은 결정 요인이 아니다.** 세로 캡처 한 장에 Gemini 2.5 Flash 와 gpt-5-mini 는 약 $0.0014,
  Haiku 4.5 는 약 $0.0037 이다. 월 만 장이어도 $14~37 이라 인식률·스키마 준수·사진 보관 정책이 가른다.
- **Gemini 를 앞에 둔 이유.** 문서·영수증 추출 비교에서 정확도가 위쪽이고, 세로 캡처의 이미지 토큰이
  셋 중 가장 싸며(768px 타일당 258 토큰), `responseJsonSchema` 로 우리 pydantic 스키마를 거의 그대로 받는다.
- **OpenAI 를 예비로 남긴 이유.** strict 구조화 출력이 스키마 위반을 가장 확실히 막는다. Gemini 가
  스키마를 자주 어기면 설정 한 줄로 바꾼다. 같은 이유로 Claude 는 넣지 않았다. 값이 2.6배이고
  긴 변 1,568px 축소가 긴 영수증에 불리하다.
- **SDK 를 안 넣은 이유.** 의존성 둘과 그 버전 추적이 늘고 이미지가 무거워진다. 포트가 이미 있어
  구현체가 REST 를 직접 부르는 것이 오히려 짧다. 응답 봉투가 바뀌면 그 자리 한 곳만 고친다.
- **스키마를 다듬어 보내는 이유.** pydantic 스키마에는 `$ref`·`title`·`default`·`maxLength` 가 섞여
  있고, OpenAI strict 는 모든 속성을 required 로 요구한다. `app/integrations/llm/schema.py` 가
  한 번 다듬어 두 provider 가 같은 모양을 받는다. 검증은 어차피 pydantic 이 다시 한다.

## 대안

- **키 하나(`LLM_API_KEY`)로 provider 를 갈아 끼운다.** 버렸다. provider 와 키가 어긋나면 첫 요청에서야
  401 이 난다. 키를 provider 별로 두면 바꿀 때 환경변수 한 줄이다.
- **provider SDK(google-genai · openai)를 쓴다.** 버렸다. 위 근거.
- **OCR 을 먼저 돌려 글자만 보낸다.** 버렸다(ADR-0010). 원본이 OCR provider 로 가서 문제를 옮길 뿐이다.
- **운영에서 `stub` 을 금지한다.** 버렸다. 화면이 「아직 예시 결과예요」 를 스스로 띄우므로 키 없이
  먼저 출시하는 길을 남긴다. 다만 기동 로그에 어떤 provider 인지 한 줄 남긴다.

## 결과

무엇을 잃는가.

- **사진이 실제로 밖으로 나간다.** 캡처의 카드번호·잔액·다른 사람 이름이 이미지 그대로 provider 로 간다.
  줄글은 보내기 전에 가리지만 사진은 가릴 수단이 없다(`docs/SECRETS.md` §4). 학습에 쓰지 않는 것은
  계약으로 확인했지만, 남용 감지 로그는 짧게 남는다.
- **인식률을 아직 재지 않았다.** 어댑터가 도는 것은 `scripts/llm_smoke.py` 로 사람이 본다. 우리 영수증
  스무 장으로 셋을 한 번 돌려 보기 전에는 Gemini 가 최선이라고 말할 수 없다.
- **비용 상한이 없다.** `NL_PARSE_DAILY_LIMIT`(사용자당 하루 300건)만 있고 사진과 줄글을 따로 세지 않는다.
  실제 사용량을 보고 가른다.
- **모델 버전은 우리가 따라가야 한다.** `gemini-2.5-flash` 가 내려가면 `LLM_MODEL` 로 바꾼다. 3.x Flash 는
  2026-12-31 까지 할인가이고 그 뒤 두 배다.
