# 0014. PATCH 에서 null 의 뜻을 필드마다 정한다

상태: 확정 · **PRD 가 정하지 않아 우리가 정했다** · 2026-09-08

## 배경

`PATCH` 는 보낸 필드만 고친다. 그런데 **필드를 빼는 것**과 **`null` 을 보내는 것**은 다른
요청이고, JSON 은 그 둘을 구분해서 보낸다. 어느 쪽을 어떻게 읽을지 정하지 않으면 모듈마다
다르게 짜이고, 그 차이가 사용자에게는 오류 문구로 새어 나온다.

실제로 두 번 샜다.

- `PATCH /goals/{id}` 에 `title: null` 을 보내면 NOT NULL 위반이 409 로 나갔다.
  영영 안 되는 요청에 "잠시 후 다시 시도해 주세요" 라고 말한 셈이다.
- `PATCH /transactions/{id}` 에 `occurred_at: null` 을 보내면 시각 정규화가 `None` 에서 죽어 500 이었다.

프론트 타입은 `openapi.json` 에서 생성한다. 생성 타입은 nullable 필드를 `T | null` 로 내주므로,
그 타입만 보고 짠 클라이언트가 **런타임에야** 막힌다. 그래서 규칙을 계약에 적어 두어야 한다.

## 결정

`null` 의 뜻을 **필드마다** 정하고, 셋 중 하나로만 둔다.

| 뜻 | 어디 | 왜 |
| --- | --- | --- |
| **지운다** | 목표 `target_date` · 알림 `remind_at` · 검토 후보 `merchant`·`category_id` | '값 없음' 이 정상 상태이고, 지우는 길이 이것뿐이다 |
| **422 로 막는다** | 거래 `occurred_at`·`amount`·`type`·`excluded_from_budget` · 목표 이름·금액·시작 금액 · 검토 후보 `amount`·`type`·`is_selected`·`occurred_at` | 컬럼이 NOT NULL 이라 그대로 쓰면 409·500 으로 샌다 |
| **안 보낸 것으로 본다** | 카테고리 이름·아이콘 · 설정(`/preferences`) 전부 | 전부 기본값이 있는 컬럼이라 비워 둘 자리가 없다 |

- 막는 자리는 스키마의 `model_validator` 가 `model_fields_set` 으로 **'보냈는데 null'** 만 잡는다.
  필드를 뺀 요청과 구분되지 않으면 부분 수정 자체가 깨진다.
- 건너뛰는 자리는 서비스가 `None` 인 항목을 건너뛴다. 이 동작을 지키는 것이 코드 한 줄뿐이라
  **테스트로 못 박는다**(`test_categories.py`·`test_settings.py`).
- 이 표를 `docs/API_CONTRACT.md` 의 각 절과 스키마 docstring 양쪽에 적는다. docstring 은
  `openapi.json` 을 지나 프론트까지 간다.

## 근거

- **셋으로 나눈 이유는 컬럼이 셋으로 나뉘어서다.** 비울 수 있는 컬럼 · NOT NULL 컬럼 ·
  기본값이 있는 컬럼. 규칙을 API 가 아니라 데이터 모델에서 끌어오면 다음 필드를 더할 때도 답이 정해진다.
- **막을 것은 422 로 막는다.** 409 나 500 은 "다시 해 보면 될지도" 로 읽히는데, 이 요청은
  몇 번을 보내도 안 된다. 형식 오류라고 말해야 사용자가 고칠 수 있다.
- **전부 422 로 통일하지 않는다.** 그러면 기한·알림 시각을 지우는 길이 사라진다.
  그 자리에 `clear_target_date: true` 같은 필드를 새로 파는 것은 계약을 늘리기만 한다.
- **전부 '무시' 로 통일하지도 않는다.** 클라이언트가 지우려고 보낸 `null` 이 조용히 삼켜지면
  화면에는 지워진 것처럼 보이고 서버에는 남는다. 조용한 어긋남이 오류보다 나쁘다.

## 대안

- **모든 `null` 을 422 로 막는다.** 규칙이 하나라 외우기 쉽다. 버린 이유는 위와 같다:
  기한·알림 시각을 지울 방법이 없어지고, 지우기 전용 필드를 따로 만들어야 한다.
- **모든 `null` 을 '안 보낸 것' 으로 본다.** 서버가 절대 죽지 않는다. 버린 이유는 지우려는
  요청이 조용히 무시되기 때문이다. 화면과 서버가 다른 값을 들고 있게 된다.
- **`PUT` 으로 통째로 덮어쓴다.** 예산·자산이 이미 그렇게 한다. 거래·목표처럼 화면이 일부만
  들고 있는 자원에는 맞지 않는다. 안 보낸 값이 지워진다.

## 결과

- 필드가 늘 때 답이 이미 정해져 있다. 컬럼이 NOT NULL 이면 422, 기본값이 있으면 무시,
  비울 수 있으면 지우기다.
- 규칙이 셋이라 **어느 쪽인지 계약 문서를 봐야 한다.** 모듈마다 한 줄씩 적어 두는 값을 치른다.
- 지키는 장치가 갈린다. 막는 쪽은 검증기가, 건너뛰는 쪽은 서비스 한 줄이 지킨다.
  뒤엣것은 지워도 조용하므로 테스트가 필요하다.
