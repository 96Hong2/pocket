# 0007. 남은 일수에 오늘을 포함한다

상태: 확정 · **PRD 가 정하지 않아 우리가 정했다** · 2026-09-03

## 배경

홈 히어로에 "남은 예산 X원 · N일 동안 하루 약 Y원" 이 뜬다.
여기서 N(남은 일수)을 오늘까지 세느냐 내일부터 세느냐를 PRD 가 정하지 않았다.
사소해 보이지만 하루치 금액을 만드는 나눗셈의 분모라서 화면 숫자가 통째로 달라진다.

## 결정

```
remainingDays = (period_end - today).days + 1     # 오늘 포함
elapsedDays   = clamp(1, (today - period_start).days + 1, totalDays)
totalDays     = (period_end - period_start).days + 1
dailyAllowance = max(0, remainingBudget) / max(1, remainingDays)
```

## 근거

- **말일에 0으로 나누는 사고를 막는다.** 오늘을 빼면 9월 30일에 `remainingDays = 0` 이 되고 하루 가용액이 `ZeroDivisionError` 또는 무한대가 된다. 하필 사용자가 가장 예민한 날에 화면이 깨진다.
- **사용자 체감과 맞는다.** 30일 오전에 앱을 열면 아직 오늘 점심도 저녁도 남아 있다. "오늘 쓸 수 있는 돈" 을 알고 싶어서 여는 것인데 0일이라고 하면 말이 안 된다.
- **`elapsedDays` 와 짝이 맞는다.** 지난 일수도 오늘을 포함해 1부터 센다(1일에 열면 1일차). 한쪽만 오늘을 빼면 `elapsedDays + remainingDays` 가 `totalDays` 와 어긋난다.
- `max(1, remainingDays)` 는 이중 안전장치다. 기간이 지난 예산을 조회해도 나눗셈이 터지지 않는다.

## 대안

- **오늘 제외(내일부터 세기)**: "앞으로 남은 날" 이라는 말에는 더 가깝지만 말일 0 나눗셈을 따로 막아야 하고, 30일에 "0일 동안 하루 0원" 같은 문장이 나온다.
- **말일만 예외 처리**: 특수 케이스가 하나 늘고, 왜 그런지 아무도 기억 못 한다.

## 결과

- 계산은 `backend/app/domain` 한 곳에서만 한다. 프론트가 날짜를 다시 세지 않는다.
- pytest 로 경계값을 찍는다: 기간 첫날, 중간, 말일, 기간이 이미 끝난 예산, 하루짜리 기간(`totalDays = 1`).
- 기준 날짜는 사용자 기기 시계가 아니라 서버 기준 날짜(KST)를 쓴다. 기기 시계를 바꿔서 숫자가 달라지면 안 된다.
- 문구는 "N일 동안" 으로 쓴다. "N일 남음" 은 오늘이 포함됐는지 헷갈린다.
