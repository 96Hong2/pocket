# 0032. 가계부를 엑셀과 CSV 로 내보낸다. 파일은 기기에만 내려놓는다

상태: 확정 · **사용자가 기능을 지정했다** · 2026-09-25

## 배경

사용자가 직접 요구했다: 「가계부를 엑셀로 내려받는 기능도 만들어줘」. 다른 서비스로 옮기기 좋은
CSV 도 함께 달라고 했다.

설정 화면에는 이미 자리가 있었다. 「CSV 내보내기 · 준비 중」 이라 적힌 못 누르는 줄이고,
주석에 왜 남겨 뒀는지가 적혀 있었다: 감추면 「이 앱은 내보내기가 없다」 로 읽히고, 누를 수 있게
두면 눌러 보고 아무 일도 안 일어난다. 그 자리를 채우는 일이다.

이 기능이 파는 것은 편의가 아니라 **믿음**이다. 이 앱은 로그인 화면이 없고(ADR-0003) 기록이
서버에만 있다. 적어 둔 것을 언제든 통째로 꺼내 갈 수 있다는 것이, 몇 달치를 여기 쌓아도
되겠다고 마음먹는 조건이다. 같은 화면 맨 끝에 「앱 데이터 초기화」 가 있는 것과 짝이다.
지우고 나가는 길과 들고 나가는 길이 둘 다 있어야 한다.

인접한 두 결정과 어긋나지 않아야 했다.

- **ADR-0010** 은 캡처 원본을 서버에 남기지 않기로 했다. 밖으로 내보내는 통로를 만들면
  그 약속이 흔들릴 수 있다.
- **ADR-0019** 는 행동 로그를 토스 Analytics 하나로만 보내고, 거기에 금액·상호·메모를 절대
  싣지 않기로 했다. 「내보냈다」 를 세면서 무엇을 내보냈는지까지 세면 그 결정이 깨진다.

## 결정

**설정 화면의 그 줄을 누를 수 있는 버튼으로 바꾸고, 엑셀(.xlsx)과 CSV 를 둘 다 준다.**
라벨은 「엑셀로 내보내기」 다. 「CSV」 보다 누르기 전에 무엇을 얻는지가 분명하다.

| 항목 | 정한 것 |
| --- | --- |
| 형식 | 엑셀(.xlsx)이 기본, CSV 도 같은 시트에서 한 번에 고를 수 있다 |
| 엑셀 시트 | 「전체 내역」 · 「월별 요약」 · 「카테고리별 요약」 세 장 |
| CSV | 「전체 내역」 한 장만. 한 파일에 표가 하나뿐인 형식이다 |
| 기간 | 이번 달 · 지난 달 · 올해 · 전체. 넷뿐이다 |
| 나가는 곳 | **기기뿐이다.** 토스 SDK `File.saveBase64` 로 내려놓는다 |
| 한 번에 | 최근 1만 줄까지. 천장에 닿으면 어디부터 담겼는지 화면과 파일에 적는다 |
| 로그 | `export_result` 에 형식·기간·줄 수·결과만. **내용은 한 글자도 안 싣는다** |
| 안 쓴 날 | 표시는 안 담는다. 0원 지출로 저장돼 있어 그냥 두면 요약 건수를 부풀린다 |
| CSV 안전 | `=` `+` `-` `@` 로 시작하는 값은 앞에 작은따옴표를 붙여 수식으로 안 읽히게 한다 |

**집계는 ADR-0005 를 그대로 따른다.** 이체는 월별 요약과 카테고리별 요약에서 빠지고, 환불은
수입이 아니라 지출을 깎는다. 카테고리별 요약은 「카테고리 지출」 열 그대로라 수입이 없다.
이체는 「전체 내역」 에는 그대로 남는다. 적어 둔 것이 파일에서 사라지면 그건 다른 문제다.

**`xlsx`(SheetJS)를 넣되 동적 import 로 나눈다.** 시트를 여는 순간에만 받는다.

## 근거

- **엑셀을 요구한 사람에게 CSV 를 주는 것은 답이 아니다.** CSV 를 엑셀로 열면 한글이 깨지고
  (BOM 이 없으면), 요약도 없고, 열 너비도 없다. 열어 보는 사람에게는 엑셀이 맞다.
- **그렇다고 CSV 를 빼면 옮기려는 사람의 길이 막힌다.** 다른 가계부·스프레드시트가 받는 것은
  CSV 다. 둘은 서로 다른 사람의 것이라 하나로 합칠 수 없다. 대신 **자리는 하나**로 둔다.
  줄을 둘로 나누면 설정 화면에서 「내보내기」 가 두 번 보인다.
- **요약 두 장을 넣은 것은 표가 곧 답이 되게 하려는 것이다.** 내역만 주면 받는 사람이 피벗을
  다시 짠다. 그때 이체를 빼야 한다는 것을 아는 사람은 없고, 그러면 그 사람이 만든 숫자와
  앱 화면이 어긋난다. 우리가 아는 규칙(ADR-0005)은 우리가 계산해서 넘긴다.
- **기간을 넷으로 못 박은 이유.** 날짜 칸 둘을 세우면 이 시트가 폼이 된다. 거꾸로 고른 범위를
  잡아 줄 자리와 그 오류 문구가 따라오고, 시트를 여는 목적이 「고르기」 로 바뀐다.
- **1만 줄 천장은 두 가지를 막는다.** 커서가 같은 자리를 되풀이할 때 끝없이 도는 것, 그리고
  몇 만 줄을 한꺼번에 들고 엑셀을 만들다 WebView 가 먼저 죽는 것이다. 목록은 최근 것부터
  오므로 닿으면 최근 1만 줄이 나간다. **그 사실을 화면에 적는다.** 조용히 자르면 다 받은 줄
  알고 옛 기록을 지우는 사람이 생긴다.
- **천장에 닿은 것과 고른 기간이 잘린 것은 다르다.** 천장은 거르기 전에 걸리므로, 올해를
  고른 사람이 작년 기록 때문에 1만 줄을 채웠어도 올해치는 온전할 수 있다. 그때 「덜 받았다」
  고 말하면 같은 기간을 몇 번씩 다시 내려받는다. 받아 온 것 중 **가장 오래된 줄이 아직 고른
  기간 안에 있을 때만** 잘린 것으로 본다.
- **잘렸으면 어디서 잘렸는지까지 적는다.** 줄 수만 말하면 어느 달이 반쪽인지 알 수 없다.
  월별 요약의 그 달은 다른 달과 같은 모양으로 서 있어서, 옮겨 적으면 그대로 틀린 숫자가
  된다. 화면에 잘린 날을 적고, 엑셀 「월별 요약」 의 그 달 「비고」 칸에도 같은 말을 남긴다.
  **「기간을 나눠 한 번 더 받으라」 고는 하지 않는다.** 기간이 넷뿐이라 그 앞을 꺼낼 자리가
  실제로 없다. 월 고르기나 연 단위 조회를 붙이는 날 그 안내를 되살린다.
- **CSV 는 수식으로 읽힐 수 있어 선행 기호를 중화한다.** 엑셀·구글 시트는 `=` `+` `-` `@` 로
  시작하는 칸을 계산식으로 본다. 상호는 영수증 사진을 모델이 읽어 채우는 칸이라 남이 쓴
  글자가 닿고, 이 파일은 애초에 배우자·세무 담당에게 넘기라고 만든 물건이다. 앞에
  작은따옴표를 붙여 글자로 묶는다. 엑셀 쪽은 `aoa_to_sheet` 가 문자열을 `t="str"` 로만 써서
  수식이 되지 않으므로 CSV 한 갈래만 고친다.
- **안 쓴 날 표시는 안 담는다.** 그것은 0원 지출로 저장된 진짜 거래다(`source='no_spend'`).
  그냥 두면 「전체 내역」 에 「지출 · 분류 없음 · 0」 줄이 서고, 카테고리별 요약의 **건수**가
  실제 지출 건수보다 커진다. 금액은 0 이라 안 틀리지만 건수 열은 그대로 거짓이 된다.
  앱 화면이 이 줄을 가르는 자(`shared/ledger/splitNoSpend.ts`)를 그대로 쓴다.
- **동적 import 는 선택이 아니다.** `xlsx` 는 그 자체로 424KB(gzip 141KB)다. 정적으로 실으면
  가계부를 한 번도 안 내보내는 사람까지 첫 화면에서 그만큼을 받는다. 미니앱은 첫 로딩이 곧
  이탈이다(`docs/DEPENDENCIES.md`). 나눠 두면 첫 화면이 받는 양은 1KB 아래로 늘어난다.
- **ADR-0010 과 부딪히지 않는다.** 내보내는 것은 저장된 기록(날짜·금액·상호·분류·메모)이지
  캡처 원본이 아니다. 원본은 여전히 서버에 없다.
- **ADR-0019 와도 부딪히지 않는다.** 로그에 싣는 것은 형식·기간·줄 수·결과 네 가지뿐이다.
  파일 안의 값은 로그로 한 글자도 나가지 않는다. 「내보냈다」 는 사실만 센다.

## 대안

- **서버가 파일을 만들어 메일로 보낸다**: 큰 기록도 감당하고 기기 저장 API 도 안 탄다. 그런데
  이 앱에는 메일 주소가 없어도 되는 사람이 대부분이고(ADR-0003·0021), 파일을 만들자고 메일을
  묻는 순간 「내 데이터를 꺼내는 데 계정이 필요한 앱」 이 된다. 그리고 우리가 사용자의 기록
  전부를 담은 파일을 만들어 서버에 두게 된다. 안 만드는 쪽이 낫다.
- **CSV 만 준다**: `xlsx` 를 안 넣어도 되고 코드가 절반이다. 사용자가 명시적으로 엑셀을 요구했고,
  요약 두 장이 이 기능의 값어치 중 절반이다. 버렸다.
- **`xlsx` 를 안 쓰고 직접 만든다**: xlsx 는 XML 몇 장을 zip 으로 묶은 것이라 만들 수 있다.
  다만 zip 라이브러리가 새로 필요하고(그것도 의존성이다), 시트·열 너비·인코딩을 우리가 다시
  맞춰야 한다. 동적 import 로 첫 로딩 비용을 0 으로 만들 수 있으므로 직접 만들 이유가 없다.
- **공유 시트로 내보낸다(`share`)**: 이미 브릿지에 있는 통로다. 그런데 그건 링크를 보내는
  자리지 파일을 보내는 자리가 아니다. 파일을 넘길 수 없다.
- **날짜 범위를 직접 고르게 한다**: 위 「근거」 의 이유로 버렸다. 「올해」 와 「전체」 사이가
  실제로 아쉬워지면 그때 넣는다.

## 결과

- **잃는 것: 앱 번들이 커진다.** `.ait` 가 1.85MB → 1.90MB 로 늘었다(늘어난 144KB 중
  대부분이 `xlsx` 청크다). 첫 화면이 받는 양은 1KB 아래로만 늘지만, 번들 자체는 커졌다.
  이 앱에서 한 기능이 이만큼을 가져간 적이 없다.
- **잃는 것: 낮은 토스 앱 버전에서는 못 쓴다.** `File.saveBase64` 는 Android 5.218.0 ·
  iOS 5.216.0 이상이다. 그 아래에서는 버튼이 서지만 눌러도 저장이 안 되므로, 필요한 버전
  숫자와 지금 버전을 나란히 적어 준다. 「업데이트하세요」 만 말하면 이미 최신인 사람이
  무엇을 해야 할지 모른다.
- **잃는 것: 저장된 뒤를 우리가 모른다.** SDK 가 결과를 돌려주지 않는다. 사용자가 저장 창에서
  취소했는지 정말 저장했는지 알 수 없어, 로그는 「던졌다」 까지만 센다.
- **`xlsx` 는 npm 에서 0.18.5 가 마지막이다.** SheetJS 가 그 뒤 판을 자기 CDN 으로만 낸다.
  `npm audit` 에 high 하나가 남고 고칠 판이 없다. 두 건 모두 **파일을 읽는 경로**의 문제이고
  (프로토타입 오염 · ReDoS), 우리는 쓰기만 한다. 자세한 것은 `docs/DEPENDENCIES.md`.
- 파일 이름은 `가계부_2026-09.xlsx` 처럼 기간이 들어간다. 이름만 보고 무엇인지 알아야
  내려받은 폴더에서 다시 찾는다.
- 계산은 `frontend/src/features/export/rows.ts` 한 곳에서만 한다. 화면이 부호나 제외 규칙을
  다시 만들지 않는다. 이체 제외·환불 차감·금액 변환·CSV 인용·수식 중화·안 쓴 날 제외는
  단위 테스트로 못 박았다.
- **xlsx 는 압축해서 쓴다.** SheetJS `write` 의 기본값이 무압축(zip STORED)이라, 1만 줄짜리가
  base64 로 4.5MB 가 되고 그 문자열이 그대로 JS↔네이티브 브릿지를 건넌다. `compression: true`
  한 줄로 크기가 3배, 만드는 동안 쓰는 힙이 2배 줄었다. 속도는 시트 구성에 따라 오르내려
  근거로 쓸 수 없다. 실기기에서 1만 줄을 한 번 돌려 보고 `MAX_ROWS` 를 다시 정할 일이 남았다.

## 뒤집을 조건

- 기록이 1만 줄을 넘는 사람이 실제로 나오면(로그의 `rows` 가 천장에 붙으면) 서버가 파일을
  만드는 길을 다시 본다. 그때는 위 대안의 「메일」 이 아니라 **내려받기 주소를 잠깐 여는**
  쪽이다. 우리가 파일을 오래 들고 있지 않는다.
- `export_result` 의 `format` 이 한쪽으로 크게 기울면 안 쓰는 쪽을 뺀다. 자리 하나에 버튼이
  둘 서 있는 값을 못 하고 있다는 뜻이다.
