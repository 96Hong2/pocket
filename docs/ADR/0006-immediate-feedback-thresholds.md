# 0006. Immediate Feedback 임계값

상태: 확정 · **PRD 가 정하지 않아 우리가 정했다** · 데이터가 쌓이면 재조정 · 2026-09-03

## 배경

이 앱의 핵심은 저장 직후 한 문장이다. PRD 는 다섯 단계(초과 / 주의 / 큰 지출 / 성취 / 적정)와 우선순위까지 정했지만 "얼마부터 큰 지출인가", "얼마나 빨라야 주의인가" 는 숫자를 적지 않았다.
숫자가 없으면 매번 다른 문장이 뜨고, 사용자는 이 앱의 경고를 안 믿게 된다.

## 결정

우선순위는 `초과 > 주의 > 큰 지출 > 성취 > 적정` 이고 한 번에 한 단계만 보여준다.

- **초과**: `remainingBudget < 0` 또는 방금 저장한 카테고리가 그 카테고리 예산을 넘김. **예측이 아니라 실제 초과만.**
- **주의**: `elapsedDays >= 3` 이고 (`paceRatio >= 1.2` 또는 `projected > budget.amount`)
- **큰 지출**: `amount >= max(30000, 해당 카테고리 최근 90일 지출 중앙값 × 3, budget.amount × 0.10)`
- **성취**: 실제 데이터로 확인되는 것만. 주간 지출 감소 / 무지출 2일 연속 / `projected` 가 처음으로 예산 이하가 됨. 해당 없으면 **아무것도 표시하지 않는다.**
- **적정**: 위 어디에도 안 걸림 → `남은 예산 X원 · N일 동안 하루 약 Y원`
예산이 없으면 큰 지출·성취만 시도하고, 그것도 없으면 `이번 달 지출 X원` 이라는 사실 문장을 보여준다.

## 근거

- **`elapsedDays >= 3`**: 월초 하루이틀 치로 뽑은 `projected` 는 요동이 너무 크다. 1일에 5만원 쓰면 예상 지출이 150만원이 된다. 첫 사흘은 경고하지 않는다.
- **`paceRatio >= 1.2`**: 페이스보다 20% 빠른 정도면 사용자가 조절할 수 있는 폭이다. 1.1 은 자주 떠서 무뎌지고, 1.5 는 이미 늦다.
- **큰 지출의 세 값 중 최댓값**: 절대액 3만원만 쓰면 예산 30만원인 사람에게는 너무 자주 뜨고 300만원인 사람에게는 안 뜬다. 카테고리 중앙값 3배는 "평소와 다르다" 를 잡고, 예산의 10% 는 예산 규모에 맞춘다. 셋 중 가장 큰 값을 써서 과잉 알림을 막는다.
- **중앙값 90일**: 평균은 이상치 한 건에 끌려간다. 90일이면 계절성 없이 최근 습관을 담는다.
- **성취는 만들어내지 않는다**: 근거 없는 칭찬은 신뢰를 깎는다. 실제 데이터로 확인되는 것만 말한다.
- **초과에 예측을 넣지 않는 이유**: 예측 초과는 "주의" 의 몫이다. "초과했어요" 는 실제로 넘었을 때만 써야 무게가 있다.

## 대안

- **PRD 가 정할 때까지 문장을 안 보여준다**: 핵심 기능이 없는 앱이 된다.
- **전부 사용자 설정으로 뺀다**: 설정이 늘고 "필수 질문 0개" 원칙과 충돌한다.

## 결과

- 임계값은 `backend/app/domain` 의 상수 한 곳에 모은다. 화면과 프롬프트에 흩어 두지 않는다.
- 단계 선택은 deterministic 코드가 한다. LLM 은 고른 단계를 문장으로 다듬을 뿐 숫자를 만들지 않는다.
- `projected` 는 `elapsedDays < 3` 이면 계산은 하되 노출하지 않는다.
- 실사용 데이터가 쌓이면 "주의가 며칠에 몇 번 떴는지" 를 보고 1.2 와 90일 창을 다시 잡고 이 문서를 갱신한다.
