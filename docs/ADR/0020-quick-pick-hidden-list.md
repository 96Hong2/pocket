# 0020. 기록 화면에 보일 분류는 사용자 설정에 '숨긴 것'으로 적는다

상태: 확정 · 2026-09-12

## 배경

기본 지출 분류가 열하나까지 늘면서 기록 시트의 칩이 네 줄을 먹었다. 사용자가
「기록 시에 메인으로 보여줄 카테고리들도 카테고리 설정에서 사용자가 직접 고를 수 있으면
좋겠어」라고 요청했다.

값을 어디에 둘지가 문제였다. 이 값은 **사람마다 다르다.** 그런데 고르는 대상의 대부분은
기본 분류이고, 기본 분류는 `user_id IS NULL` 인 **한 행을 모든 사용자가 함께 본다.**

그리고 이미 쓰고 있는 사람이 있다. 어떻게 두든 마이그레이션 한 번으로 그 사람들의 기록
화면이 비면 안 된다.

## 결정

**`user_preferences.quick_hidden_category_ids` (JSON 배열) 하나에, 보일 것이 아니라
`숨긴 것`의 id 를 적는다.**

- 비어 있는 것이 곧 「전부 보인다」다. 기본값에 손댈 일이 없다
- `GET /categories` 가 이 목록을 읽어 카테고리마다 `is_quick` 을 **계산해서** 내려준다.
  화면은 `category.is_quick` 하나만 보면 된다
- `PATCH /categories/{id}` 의 `is_quick` 만은 **기본 분류에도 걸린다.** 이름·아이콘과 달리
  카테고리 행을 건드리지 않고 내 설정에만 남기 때문이다
- 화면은 켠 것을 앞에 세우고 끈 것을 「N개 더」 뒤로 보낸다. **없애지 않는다**

## 근거

- **사람마다 다른 값을 공용 행에 적을 수 없다.** `categories.is_quick` 컬럼으로 뒀다면
  한 사람이 '기타' 를 끈 순간 전부에게 꺼진다. 처음에 그렇게 만들었다가 되돌렸다
- **숨긴 것을 적으면 기본값이 저절로 맞는다.** 보일 것을 적으면 분류가 하나 생길 때마다
  이 목록을 함께 고쳐야 하고, 한 번이라도 빠뜨리면 방금 만든 분류가 어디에도 안 나온다.
  이미 쓰던 사람의 화면이 마이그레이션 하나로 비는 일도 없다
- **`is_quick` 을 계산해서 내려주면 화면이 저장 구조를 몰라도 된다.** 나중에 저장 자리를
  옮겨도 프론트는 그대로다
- 값은 작고(id 몇 개), 한 사용자에 하나이며, 다른 사용자와 엮어 질의할 일이 없다.
  관계로 만들 이유가 없다

## 버린 안

- **`categories.is_quick` 컬럼**: 가장 짧다. 목록 API 도 그대로다. 대신 **기본 분류에서
  작동하지 않는다.** 한 사람이 끈 것이 모두에게 꺼진다. 사용자가 고르고 싶어 한 대부분이
  기본 분류라 이 안은 요구를 아예 못 채운다
- **`user_category_settings` 조인 표(user_id, category_id, is_quick)**: 정규화돼 있고 FK 로
  묶여 지운 분류의 흔적이 안 남는다. 대신 모델·마이그레이션·질의·조인이 새로 생긴다.
  한 사용자에 id 몇 개인 값에 표 하나는 값이 크다
- **보일 것(`quick_category_ids`)을 적는다**: 「고른 것」이라 읽기가 자연스럽다. 대신
  `null = 전부` 라는 규칙이 필요하고, 처음 하나를 끄는 순간 **현재 전체 목록을 물질화**해야
  한다. 그 물질화 시점에 없던 분류는 영영 안 보인다. 규칙이 하나 더 생기고 그 규칙이 함정이다

## 무엇을 잃는가

- **지운 분류의 id 가 목록에 남는다.** FK 가 아니라 JSON 이라 정리되지 않는다. 있는지만
  보는 값이라 동작에는 지장이 없지만, 오래 쓰면 죽은 id 가 쌓인다
- **"누가 무엇을 숨겼나" 를 SQL 로 집계하기 어렵다.** JSON 안을 들여다봐야 한다. 지금은
  집계할 계획이 없다
- **`PATCH /categories/{id}` 의 뜻이 필드마다 갈렸다.** 이름·아이콘은 내가 만든 것만,
  `is_quick` 은 기본 분류도. 라우터에 그 갈림이 드러나 있고 테스트가 양쪽을 다 지킨다
- 한 사용자의 설정 행이 조금 커진다. 분류 수만큼이라 상한이 낮다
