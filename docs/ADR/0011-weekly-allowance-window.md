# 0011. 주간 가용액은 월~일 중 이 달에 남은 날로 센다

상태: 확정 · **PRD 가 정하지 않아 우리가 정했다** · 2026-09-07

## 배경

홈 히어로에 "하루 약 17,428원" 이 이미 뜬다. 그런데 하루치만 보면 이번 주말 나들이나 외식을
가늠할 수 없다. 하루 단위로 아껴 쓰는 사람은 드물고, 대부분 "이번 주에 이만큼" 으로 생각한다.

그래서 "이번 주 쓸 수 있는 돈" 을 한 줄 더 붙이기로 했는데, PRD 가 두 가지를 정하지 않았다.
한 주를 어디서 끊나(월요일 시작인가 일요일 시작인가, 아니면 오늘부터 이레인가), 그리고
그 주가 달을 넘어갈 때 넘어간 날까지 세는가.

## 결정

```
week           = 오늘이 속한 월요일~일요일 (사용자 시간대)
weekDaysLeft   = 오늘부터 min(week.end, period.end) 까지의 날 수   # 오늘 포함
weeklyAllowance = dailyAllowance × weekDaysLeft
```

- 예산이 없으면 `weeklyAllowance` 는 `null` 이다. 0 으로 적지 않는다.
- 남은 예산이 음수면 `dailyAllowance` 가 0 이므로 주간 값도 0 이다(ADR-0007 과 같은 규칙).
- 보고 있는 기간 안에 오늘이 없으면(지난달을 열어 본 것) `weekDaysLeft` 는 0 이다.

## 근거

- **월요일 시작이 한국 달력과 맞는다.** 사용자가 보는 달력 앱과 주 경계가 같아야 "이번 주" 가
  같은 뜻이 된다. 오늘부터 이레로 잡으면 매일 창이 밀려서 어제 본 숫자와 오늘 본 숫자가
  같은 기간을 가리키지 않는다.
- **달 경계에서 잘라야 두 숫자가 안 싸운다.** 9월 30일이 수요일이면 주는 10월 4일까지지만
  9월 예산으로 쓸 수 있는 날은 30일 하루다. 잘라 주지 않으면 "이번 주 쓸 수 있는 돈" 이
  "남은 예산" 보다 커지고, 한 화면에 있는 두 숫자 중 어느 쪽을 믿어야 할지 알 수 없다.
  자르면 달 마지막 주에는 주간 값이 남은 예산과 같아져 두 줄이 자연스럽게 맞는다.
- **하루치를 곱한다. 남은 예산을 다시 나누지 않는다.** 나눗셈을 두 번 하면 내림이 두 번 걸려
  `하루치 × 남은 날` 과 주간 값이 어긋난다. 화면의 두 줄이 서로 안 맞으면 계산을 의심하게 된다.
- 이미 있는 `week_to_date`(지난주와 견주는 창)를 쓰지 않는다. 저건 아직 안 지난 날을 일부러
  빼는 창이고, 여기는 앞으로 남은 날을 세는 창이다. 같은 함수로 둘을 겸하면 한쪽이 틀린다.

## 대안

- **오늘부터 이레**: 언제 봐도 이레라 계산이 단순하지만, 창이 매일 밀려 "이번 주" 라고 부를 수
  없다. 주말이 두 번 들어가는 창도 생긴다.
- **달 경계로 자르지 않기**: 마지막 주에 다음 달 며칠이 섞인다. 아직 정하지도 않은 다음 달
  예산에서 미리 꺼내 쓰라고 말하는 셈이다.
- **남은 예산 ÷ 남은 주 수**: 주 단위로 나누면 첫 주와 마지막 주가 며칠뿐일 때 값이 튄다.

## 결과

- 계산은 `backend/app/domain/budget.py` 의 `week_days_left` 와 `evaluate_budget` 한 곳이다.
  주 경계 자체는 `domain/period.py` 의 `week_containing` 이 만든다. 화면은 곱하지 않는다.
- 응답에 `weekly_allowance` · `week_days_left` · `week_start` · `week_end` 를 함께 싣는다.
  화면이 요일을 다시 세지 않게 창까지 준다.
- pytest 로 경계를 찍는다: 달 중간 주, 달 마지막 주(잘림), 예산 없음, 기간 밖.
  e2e 는 이번 주에 남은 날 수를 spec 이 직접 세어 화면 숫자와 견준다.
- 문구는 "이번 주 쓸 수 있는 돈" 이다. "남은 주간 예산" 은 따로 정한 예산이 있는 것처럼 읽힌다.
