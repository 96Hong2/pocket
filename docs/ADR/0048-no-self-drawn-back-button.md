# 0048. 시트와 창 안에 뒤로 버튼을 그리지 않는다

상태: 확정 · 2026-10-07 · 토스 검토 반려에서 왔다 · **ADR-0044 의 「시트 안 ‹」 와 `SheetHeader` 의 왼쪽 ‹ 를 대체**

## 배경

번들 20261007-60 이 토스 검토에서 반려됐다. 사유 원문은 이렇다.

「내비게이션 바의 뒤로가기 버튼과 미니앱 자체 헤더 및 뒤로가기 버튼이 함께 노출돼요. 중복된 버튼을 제거해 주세요.」

기록 두 화면 판(ADR-0044)부터 시트와 창 머리 왼쪽 위에 앱이 ‹ 를 그렸다. 사용자 지시 「모든 화면에서
뒤로가기가 가능하도록 해줘」 를 화면 안 버튼으로도 풀었던 것이다. 토스 상단바는 `withBackButton: true` 라
늘 ‹ 가 있어서, 시트가 뜨면 화면에 뒤로가기가 둘이었다. 공개판 56 에는 시트 안 ‹ 가 없었다.

「새 분류 만들기」 맨 위 줄에는 그 전부터 「이전」 글자 버튼이 있었다. 왼쪽에 나가는 버튼, 가운데 제목,
아래 구분선이라 상단바를 하나 더 그린 모양이고, 같은 사유에 걸릴 수 있다.

## 결정

- **앱은 뒤로 버튼을 그리지 않는다.** 경로 화면에 더해 시트, 화면을 덮는 창, 시트 안 단계 화면 전부다.
  ‹, ←, 꺾쇠 그림, 「뒤로」, 「이전」 글자 버튼이 모두 해당한다
- **뒤로 가는 길은 그대로 둔다.** 토스 상단바 ‹ 와 폰 뒤로가기(브릿지 `backEvent` → `BackHandler` →
  `useOverlayBackClose`), Esc, 시트와 창을 아래로 미는 손짓이다. 단계가 있는 흐름(기록 첫 화면과 둘째 화면,
  「다른 곳」 목록과 「새 종목이나 통장」, 태그, 날짜)은 토스 ‹ 로 한 단계씩 물러난다
- **머리는 제목 줄이다.** 제목은 본문과 같은 왼쪽 여백에서 시작하고 오른쪽에 칸 하나(태그 칩, 「저장」)를
  둘 수 있다. 가운데 정렬 제목과 아래 구분선을 두지 않는다. 제목 없이 ‹ 만 있던 저장 뒤 화면 셋은 머리 줄을 없앴다
- ‹ 가 「확인」 과 같은 일을 하던 저장 뒤 화면은 맨 아래 「확인」 이 그 일을 한다. 토스 ‹, 폰 뒤로가기, Esc 도
  같은 함수를 타서 적어 둔 상호와 메모를 보내고 닫는다
- 오른쪽 위 닫기(X)는 지금처럼 두지 않는다. 토스가 그리는 미니앱 닫기 자리다
- `record_back.how` 를 걷는다. 시트 안 ‹(`sheet`)가 없어져 남은 값이 하나뿐이다

## 근거

- 반려 사유가 버튼 중복이다. 둘 가운데 상단바는 플랫폼 것이라 우리가 걷을 수 있는 쪽은 화면 안 버튼이다
- 뒤로 가는 기능은 이미 토스 ‹ 에 물려 있었다. 화면 안 버튼은 같은 함수를 부르는 두 번째 입구였다.
  걷어도 못 돌아가는 화면이 생기지 않는다
- 경로 화면(`AssetAnalysisPage`, `ReportCategoryPage`)은 처음부터 이렇게 했다. 같은 원칙을 시트와 창으로 넓힌 것이다

## 대안(버린 안)

- **시트 ‹ 를 두고 토스 상단바 ‹ 를 끄기**: `withBackButton` 은 앱 전체에 한 번 걸리는 설정이라 끄면 관리 탭
  하위 화면과 리포트 분류 화면에서 뒤로 갈 버튼이 사라진다. 설치된 SDK 3.2.0 타입에는 상단바 ‹ 를 화면마다
  켜고 끄는 함수가 없다
- **시트 ‹ 를 그대로 두고 다시 내기**: 검토자가 본 화면이 바로 그 시트 머리다. 다시 반려되면 출시가 한 번 더 밀린다
- **오른쪽 위 닫기(X) 버튼으로 바꾸기**: 토스가 그리는 미니앱 닫기와 같은 자리, 같은 모양이라 시트를 닫으려다
  앱을 닫는다(실기기에서 있던 일이다. `BottomSheet` 주석). 닫기는 「한 단계 뒤로」 도 아니다
- **본문 아래에 「뒤로」 버튼 줄 두기**: 단계마다 줄이 하나 늘어 키패드가 밀린다. ADR-0044 가 지키려던 것이
  둘째 화면의 키패드 자리다

## 잃는 것

- 화면 안에서 손 닿는 자리에 뒤로 버튼이 없다. 한 단계 뒤로 가려면 화면 맨 위 토스 ‹ 나 폰 뒤로가기를 쓴다.
  **iOS 는 폰 뒤로가기 버튼이 없어 확실한 길이 토스 ‹ 하나다.** 웹뷰의 스와이프 뒤로가기는 꺼 두었고
  (`allowsBackForwardNavigationGestures: false`), 토스 앱의 가장자리 스와이프가 `backEvent` 로 오는지는
  실기기에서 확인하지 못했다. 시트를 내리는 손짓은 닫기지 한 단계 뒤로가 아니다
- 화면을 덮는 「어디에」 창(`AssetDestPage`)은 미는 손짓을 받지 않는다. 고르지 않고 나가는 길은 토스 ‹,
  폰 뒤로가기, Esc 다
- 시트 안 ‹ 와 토스 ‹ 가운데 무엇을 더 쓰는지 로그로 가를 수 없다

## 결과

- 부품: `SheetHeader` 는 제목과 오른쪽 칸만 그린다. `features/assets/SheetBackHead` 는 지우고 자산 창 셋이
  `SheetHeader` 를 쓴다. `CategoryEditForm` 의 한 화면 줄은 제목과 「저장」 만 남는다. `AssetDestFlow` 의 단계는
  쓰는 쪽이 쥔다(뒤로 버튼이 없어 물러나는 일은 쓰는 쪽이 받는다)
- 포커스: 단계가 바뀌면 새 화면의 제목(`h2`)이 포커스를 받는다. 예전에는 첫 버튼인 ‹ 가 받았다
- 로그: `record_back` 에서 `how` 를 뺐다. `docs/ANALYTICS.md` 「판마다 바뀐 값: 뒤로 버튼 걷은 판」 에 적었다
- 지키는 장치: `frontend/e2e/specs/no-self-drawn-back.spec.ts` 가 시트와 창을 하나씩 열어 이름이 「뒤로」, 「이전」,
  ‹, ← 인 버튼이 0개인지 센다. 경로 화면은 `assets.spec.ts`, `goal.spec.ts` 가 같은 자로 잰다
- e2e 의 `RecordSheet.back()` 은 토스 ‹ 와 같은 신호(`pressSystemBack`)를 쏜다
