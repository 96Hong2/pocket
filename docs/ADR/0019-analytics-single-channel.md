# 0019. 행동 로그는 토스 Analytics 하나로만 보낸다

상태: 확정 · 2026-09-11

## 배경

출시를 앞두고 CX 지표가 필요해졌다. 알고 싶은 것은 "사용자가 무엇을 썼나" 가 아니라
**"어디서 얼마나 고생했나"** 다. 첫 기록을 못 마치는 사람이 어디서 멈추는지, 캡처 인식이
실제로 몇 초 걸리는지, 읽어 온 결과를 어느 칸에서 자꾸 고치는지.

쌓을 자리를 정해야 했다. 우리 백엔드에 이벤트 테이블을 만드는 길, 외부 분석 도구를 붙이는 길,
이미 있는 토스 Analytics 를 쓰는 길이 있었다.

## 결정

**토스 공식 Analytics(`Analytics.log`) 하나만 쓴다.** 자체 이벤트 테이블도, 외부 분석 도구도
만들지 않는다. 화면은 `shared/analytics` 의 로거만 부르고, 그 안에서 브릿지를 지나 SDK 로 간다.

무엇을 남기고 무엇을 남기지 않는지는 `docs/ANALYTICS.md` 가 정본이다.

## 근거

- **수집 경로가 하나여야 "무엇이 어디에 남는가" 에 답할 수 있다.** 이 앱은 금융 화면이다.
  경로가 둘이면 개인정보 안내와 실제 수집이 어긋나는 날이 오고, 그때 어느 쪽이 샌 것인지
  아무도 모른다.
- **분석용 사용자 id·발생 시각·서버 수신 시각을 SDK 가 이미 붙인다.** 우리가 만들면 익명키를
  로그에 직접 싣게 되는데, 그건 우리가 피하려던 바로 그 일이다.
- 자체 테이블은 만드는 값이 크다. 수집 엔드포인트·재시도·보관 기간·삭제 연계를 전부 우리가
  져야 한다. 지금 필요한 것은 지표 다섯 개다.
- 외부 도구(자동 클릭 수집·세션 녹화)는 금융 화면에 불필요한 정보가 섞이기 쉽다. 켜지 않는다.

## 버린 안

- **백엔드에 `analytics_events` 테이블을 만든다**: 우리 DB 라 질의가 자유롭고 토스 콘솔에
  묶이지 않는다. 대신 수집 API·중복 제거·보관 정책·삭제 연계를 다 만들어야 하고,
  제품 DB 와 행동 로그가 같은 곳에 살아 "원본은 안 남긴다" 는 약속이 흐려진다.
- **외부 분석 SDK(GA·Amplitude 류)를 붙인다**: 대시보드가 바로 생긴다. 대신 수집 경로가
  둘이 되고, 자동 수집 기본값이 켜져 있어 우리가 안 남기기로 한 것이 섞여 들어간다.
- **아무것도 남기지 않고 지인 피드백만 듣는다**: 다섯 명까지는 그게 더 낫다. 그 뒤에는
  "어디서 막혔나" 를 물어볼 사람이 없다.

## 무엇을 잃는가

- **질의가 토스 콘솔이 주는 만큼으로 묶인다.** 코호트를 우리 마음대로 자르지 못한다.
- **과거를 소급해 못 본다.** 안 남긴 이벤트는 나중에 되살릴 수 없다. 그래서 흐름을 잇는
  `flow_id` 와 소요 시간처럼 나중에 만들 수 없는 값을 처음부터 넣었다.
- **로그 유실을 우리가 못 본다.** 브릿지가 실패를 삼키고 재시도 대기열도 두지 않아서,
  지표가 조금씩 적게 잡힐 수 있다. 비율로 보는 지표라 감수한다. 반대로 재전송을 붙이면
  로그가 기록·저장을 늦추는 날이 오는데, 그쪽이 훨씬 나쁘다.
- 운영 판에서는 우리 화면으로 로그를 확인할 방법이 없다. 개발·샌드박스에서만
  `window.__pocketLogs` 에 사본이 남는다.
